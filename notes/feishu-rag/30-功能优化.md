# 功能优化



请实现以下功能

1. Milvus 的 Schema 变动后（配置和数据库不一致），需要更新Schema
2. Milvus Schema需要添加space_title字段，用于记录所在知识库的标题，对于已存在的数据，请获取知识库标题更新它们

## 已完成

1. `init_store()` 对比配置 Schema 与实际集合，支持原地新增可空标量字段、扩容非主键 VARCHAR 字段长度；配置无变化时不写入。向量维度、字段类型、删除字段、nullable、分析器及 Function 等不兼容差异在任何 Schema 写入前明确报错，保留集合和数据。
2. Schema 新增 `space_title: VARCHAR(300), nullable=True`，新文档索引通过 `WikiAPI.get_space()` 获取知识库名称并写入 metadata。历史标题使用官方 SDK 局部更新，不重新向量化。

历史数据回填命令（按当前 Milvus/Nacos 配置执行，先暂停并发入库）：

```sh
uv run python -m deal_pilot.rag.store.feishu_doc.backfill_space_titles
```

命令先同步 Schema，再分批回填 NULL/空标题；失败可重跑，已有非空标题不覆盖。`get_store()` 缓存建立后不会持续刷新配置，修改 Schema 后需显式调用 `init_store()` 或重启进程后首次获取 store。

2026-10-23 已完成真实回填：`deal_pilot.feishu_doc` 的 206 条有效切片、6 个知识库全部有标题；更新前后的旧字段（含正文、稠密向量）摘要、集合 ID、加载状态及索引名称一致。未重跑索引图或调用 Embedding 服务。

验证命令：

```sh
.venv/bin/pytest -q tests/units/test_feishu_doc_schema.py
MILVUS_INTEGRATION=1 .venv/bin/pytest -q tests/intergrations/test_feishu_doc_schema.py
```

集成测试使用真实 Milvus 随机隔离数据库，结束后清理；Nacos 配置和飞书标题来源为 Mock。实际业务回填使用真实 Nacos、飞书和 Milvus。
